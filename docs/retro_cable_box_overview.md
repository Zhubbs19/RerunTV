Retro Cable Box is an Electron desktop app that simulates an always-live broadcast cable box: folders of video from the user's own media library are mapped to numbered channels, and playback position is always derived from the wall clock (`viewNow() = Date.now() + timeOffsetMs`, anchored per channel) rather than tracked/resumed — tuning to a channel computes what would be airing right now, like flipping to a real live channel mid-show.

As of 2026-08-04 the app is on Electron `^43.2.0` (upgraded from `^31.0.0` after a feasibility review — see [[retro-cable-box-electron-43-upgrade]]) and electron-builder `^26.15.3`. The renderer is 14 hand-split ES modules (no bundler) served over a custom `app://` protocol with full HTTP Range support, because Chromium won't load ES modules or stream `file://` media from a non-`file://` origin. Full feature set (as of this date): multi-folder channels, dayparting/schedule blocks with per-block content and/or ad overrides, three-tier commercial-break system (box-wide → per-channel → per-block, with interval/pre-show/post-show/both timing modes), a time-grid guide, channel icons/accent colors, CH1 Prevue-style barker channel and CH2 public-access channel (both can carry looping background audio), EAS test with dual-tone attention signal + text-to-speech voiceover, up-next banner, logo bug, power on/off with CRT collapse animation, auto-standby, synthesized Web Audio SFX, CRT visual effects with intensity sliders, a VCR-shuttle "time machine" mode, and automatic codec-failure detection/transcoding.

On 2026-08-05, two large sessions landed against an external spec handoff doc (`programming-blocks-and-interstitials-spec.md`) — see [[retro-cable-box-interstitials-spec-progress]] for the detailed phase-by-phase status. In short: `ch.blocks[]`/`ch.dateOverrides[]` were unified into one trigger-based (`dayOfWeek`/`dateRange`) block schema with `daily`/`weekly` advent-calendar modes (day-index content selection, per-date `dayOverrides`, `finale`), and the old commercials/station-ID/trivia systems were replaced with one shared, deterministic tagged-interstitials pool (`renderer/js/interstitials.js`) — break timing and bumper/fact/station-ID selection are now a pure function of `viewNow()` (see [[retro-cable-box-architecture-constraints]]), which also means the time-machine VCR shuttle can now preview exactly what break would be airing at any scrubbed past or future instant, not just live "now." Same session: fixed/tuned the CRT `.crt-flicker` effect (was too strong by default) and added a fourth CRT intensity slider (FLICKER, alongside SCANLINES/VIGNETTE/GRAIN) so it's user-adjustable rather than a fixed value.

Later on 2026-08-05 (session 3), a bug-fix pass on the interstitials work from earlier the same day: commercial/bumper cuts now fade to black on both entry and exit (`#player.screen-fade-out` in `tv.css`, `fadeOutPlayer`/`fadeInPlayer` in `playback.js`) instead of an abrupt `src` swap; live content now pauses through a break and resumes exactly where it left off rather than skipping ahead by the break's length (a genuine, user-directed reversal of the earlier "breaks don't consume timeline time" design — see [[retro-cable-box-architecture-constraints]] for the full mechanism and caveats); and two time-machine resume bugs were fixed — `startShuttle` was leaving break-tracking state stale for the whole shuttle session (corrupting resume if you shifted time while a break was on screen), and `exitTimeMachine`'s default path never actually resumed playback at all when exiting mid-shuttle via the `T` key (see [[retro-cable-box-architecture-constraints]]'s "state that only makes sense during continuous real-time playback" entry). Also fixed a real (not just cosmetic) race in `shuttlePlay`/`returnToLive`: both called `playChannelLive` without awaiting it before calling `checkBreakState`, letting two async `player.src` swaps race — now awaited, matching `tuneToChannel`'s existing pattern. The per-channel COMMERCIALS setup button was checked and confirmed working as designed (it edits `ch.commercials` timing/enabled; actual bumper videos come from the Programming tab's interstitials pool tagged to the channel or "ANY" — easy to mistake for broken if the pool has no entries for that channel).

On 2026-08-06 (session 7), a user-reported-bug + two-feature batch: fixed the "commercials cut off / prolonged black screen after a break" bug — `endBreak` was firing `fadeInPlayer()` immediately after `playChannelLive` returned (before the resumed video had actually decoded a frame), and the boundary timer could cut a bumper off mid-play if its once-probed duration (`probeDuration`, `setup-util.js`) undershot the real file. Fixed via `S.awaitingBumperEnd`/`S.breakOverrunSince` (playback.js) — `checkBreakState` now grants a bounded 8s grace period to a still-genuinely-playing real-file bumper instead of cutting it off on schedule — and a new `opts.fadeInOnReady` on `playChannelLive` that gates the reveal on `requestVideoFrameCallback`'s first real decoded frame instead of an immediate `screen-fade-out` class removal. Also shipped: the PROGRAMMING tab's interstitials pool now groups by channel affinity into collapsible sections with a search/type/channel filter bar (`renderer/js/setup-interstitials.js`) instead of one flat unfiltered list; and a new content-tagging feature — files get a `tags` field (editable via a new TAGS column on the channel EDIT view's TITLES tab, `setup-panels.js`) and interstitial pool entries get an optional `contentTags` field (PROGRAMMING tab) so a specific ad can be restricted to play only around tagged content, threaded through `poolFor`/`buildPod`/`windowFor` in `interstitials.js` as an additional (not replacing) filter alongside channel/block affinity. Note: block-owned file lists (`block.files`, separate from `ch.files`) aren't wired into the TITLES tab tagger yet — only channel-level content can be tagged today. Same session, follow-up: an entry's `contentTiming` field (`null`/'pre'/'post'/'both', UI only shown once `contentTags` is set, PROGRAMMING tab) lets a tagged commercial *force* a break to happen right at that content's boundary, independent of the channel's own commercial cadence entirely — `poolFor` (interstitials.js) excludes `contentTiming`-set entries from ordinary cadence-driven pools, and a new resolution branch in `resolveBreakAt` chains post-then-pre segments starting exactly at the real file-boundary timestamp (not ending there) to stay discoverable by `nextBreakBoundary`'s forward-only candidate scan — see [[retro-cable-box-architecture-constraints]] for why that anchoring direction matters.

**Real bug shipped and caught only by a full CDP boot test, not by per-file syntax checks**: the BOX STATUS panel's DOM refs (`boxStatusChannelsEl` etc.) were added to `dom.js` and used in `setup-channels.js`, but never added to that file's own `import {...} from './dom.js'` block — a plain `ReferenceError` at module-evaluation time (not deferred to when a function runs), which broke the entire module graph and made the app boot with `S.config.channels.length === 0` — landing on an empty setup screen with **no thrown alert and no visible error**, indistinguishable from a genuine empty-config first-run except that the real file on disk still had all 13 channels. `node --check`/`--input-type=module --check` on the individual file passed cleanly (it only parses syntax, never resolves whether a used identifier was actually imported) — the bug was only caught by actually reloading the running app with a `Page.addScriptToEvaluateOnNewDocument`-injected error listener (installing a listener via a later `Runtime.evaluate` call, after the page already finished loading, is too late to catch a boot-time exception).
**How to apply:** Every new dom.js export used in this session's batch was cross-checked afterward with `grep -rln "\bidentifierName\b" renderer/js/*.js` against each file's own import block — do this systematically for every new identifier, not just spot-check the ones that "felt risky," on any future batch that touches several files at once. And when a live-boot smoke test is warranted, install the error listener via `Page.addScriptToEvaluateOnNewDocument` *before* `Page.reload`, not via a `Runtime.evaluate` call after the page has already settled — a module-load-time `ReferenceError` throws before any post-hoc listener can be attached, and this exact gap is what let the bug through undetected on the first CDP pass this session.

**Why:** This app has been built entirely through iterative, feature-by-feature conversational requests across many sessions — there's no design doc or issue tracker, so the running feature list and architecture snapshot exist only in conversation history unless captured here.

**How to apply:** Treat this as a high-level orientation snapshot, not a substitute for reading the code — always verify specifics (exact function names, file line numbers) against the actual files before relying on them, since features keep getting added.
