The PLUGINS tab (`renderer/js/setup-plugins.js`, `renderer/css/setup.css`, `renderer/index.html`) was redesigned 2026-08-17 once the installed-plugin count reached 24 (up from a handful when the tab was first built) and a flat unsorted list stopped scaling. Shipped in one pass, in both repos:

- **Live text filter** (`#plugins-filter-input`) — matches name/id/folder/description/dependency ids via a precomputed lowercase `entry.dataset.search` string, reuses the same `.filtered-out` convention the Virtual Channels sub-tab already established (see [[retro_cable_box_quality_of_life]]) rather than inventing a new one. Re-applied after every list rebuild (RESCAN/install/enable-toggle all call `renderPluginsList()`, which wipes and rebuilds the DOM).
- **Enabled-count summary** (`#plugins-summary`, e.g. "24 OF 24 ENABLED") updated on load and on every individual enable/disable toggle without a full list rebuild.
- **Broken plugins sort to the top** — `sortPluginsForDisplay()` puts any plugin with a manifest `error` or renderer/main `loadError` first, alphabetical by name otherwise (was previously left in raw `discoverPlugins()`/filesystem-readdir order).
- **Inline `dependsOn` display** — a `REQUIRES: X, Y` line per plugin row, red/bold per-dependency if that dependency is missing, disabled, or itself errored. This closes the "plugin dependency info in PLUGINS tab UI (deferred, not started)" item from [[retro_cable_box_plugin_settings_relocation_and_eas_news_split]] — dependency info was previously only *enforced* (the disable-confirmation dialog), never actually shown.
- **Disabled rows dim** (`opacity: 0.55` + muted name color) via a `.plugin-row.is-disabled` class, toggled at render and live on checkbox change.

**Why:** the user asked directly for "better UI and usability as more plugins get added" with no further scoping — implemented by extending the exact patterns already proven elsewhere in this app (Virtual Channels' filter+collapse, the cross-tab settings search) rather than designing something new, since this codebase has a strong established convention for "many similar cards, need scannability."

**Verification:** CDP-tested against the real running app (24 real installed plugins, not a mock) — filter narrows to exact matches and shows a "no matches" message, dependency lines render correctly for all 4 plugins that actually have `dependsOn` (`party-jukebox`→Party Channel+YouTube Music, `spotify-connect`/`youtube-music`→FFmpeg Transcode, `universal-remote`→Party Channel), summary count correct, zero console errors, screenshot-confirmed visually. No config was left mutated by the test.

**Not done, out of scope for this pass:** grouping/categorizing plugins (e.g. by channel vs. core-subsystem vs. system-integration), a collapse-all-rows control (skipped — each row is already compact enough that collapsing wasn't judged worth the added interaction, unlike Virtual Channels' much taller per-channel panels).

**Update, later the same day: category tabs added.** The user came back with "plugin list is still long - sort into tabbed categories" once the list hit 24 — the filter/search from the first pass wasn't enough on its own for pure browsing. Added:
- A new **optional manifest field**, `category` (one of `"channel"`/`"onscreen"`/`"system"`) — documented in `PLUGIN_DEVELOPMENT.md`'s manifest table, exposed through `discoverPlugins()` (`main-plugins.js`) alongside the existing fields. Deliberately optional and non-behavioral (nothing keys off it besides this one UI) — an unset or unrecognized value just lands in an "OTHER" bucket, so third-party plugins predating this field (or ones that never set it) degrade gracefully rather than erroring or vanishing.
- All 24 bundled plugins categorized: 12 `channel` (anything that registers a real tunable channel number — HBO, Area 51, Spotify Connect, Party Channel, etc.), 6 `onscreen` (overlays/effects with no channel of their own — Ticker, Screensaver, Breaking News, EAS, SMPTE Test Pattern, Vintage Audio), 6 `system` (background services/integrations — FFmpeg Transcode, NOAA Weather, TMDB Metadata, Universal Remote, Party Jukebox, Video Splicer).
- Tabs (`ALL` + one per category actually present, each with a live count badge) render via `.setup-subtab-btn` styling reused outside its usual `.setup-subtabs` structural context (custom click wiring in `setup-plugins.js`, not the generic subtabs auto-wiring in `setup-settings.js`, since that mechanism assumes static sibling `.setup-subtab-panel` elements and this list is fully dynamic) — see [[retro_cable_box_architecture_constraints]] if a similar dynamic-tabs-over-a-JS-rendered-list need comes up elsewhere. **Only shown when 2+ categories actually have entries** — a small/mostly-third-party install with everything landing in one bucket doesn't get a pointless single tab.
- Category selection combines with the existing text filter via AND logic (both stored as small module-level state, reapplied together in one `applyPluginsFilter()` pass) — e.g. searching "ffmpeg" while on the CHANNELS tab correctly still shows Spotify Connect/YouTube Music, since the search haystack includes `dependsOn` ids and both are channel-category plugins that depend on FFmpeg Transcode.
- Verified via CDP: tab counts correct (24/12/6/6), clicking a tab filters to exactly that category, combined category+text search behaves correctly, zero console errors, screenshot-confirmed both the ALL and ON-SCREEN tab states.
- Synced to FOSS: 4 core files + `PLUGIN_DEVELOPMENT.md` + all 20 of FOSS's own plugin manifests (FOSS's reduced set still splits cleanly: 10 channel / 6 onscreen / 4 system). Hit [[retro_cable_box_cdp_autosave_gotcha]]'s 6th gotcha again here — had to manually sync all 24 updated manifest.json files into `userData/plugins/*/manifest.json` before the category was visible in a CDP test, since editing the repo source alone doesn't touch the already-seeded copies.
