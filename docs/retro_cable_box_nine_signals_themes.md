**The actual "looks like it was made by Claude" root cause, found 2026-08-21**: the app already had 9 theme packs installed (`analog-90s`, `digital-satellite-2000s`, `network-primetime-90s`, `uhf-public-access-80s`, `vhs-retro-80s`, `wood-console-70s`, `cyberpunk-synth`, `emerald-matrix`, `midnight-oled`) via the [[retro_cable_box_plugin_system]]'s `registerThemePack` mechanism — the complaint wasn't "the app has no real design system," it was that the real config's currently-active theme is `midnight-oled`, whose palette (`--gold:#818cf8`, `--gradient-btn: linear-gradient(...#4f46e5...)`) is a textbook Tailwind-indigo dark-mode-SaaS look — genuinely one of the more generic-reading options among otherwise distinctive real theme packs. This was discovered by an Explore agent tasked with mapping the theme architecture before a big build, whose report corrected an assumption made earlier in the same conversation (that the app only had 2 themes) — a reminder that even this session's own recent turns can go stale the moment a background exploration actually reads the code.

**What shipped**: 9 more theme packs, each following the exact `plugins/theme-analog-90s/` template (`manifest.json` + `renderer.js` calling `registerThemePack(id, {label})` + `style.css` with a full `html[data-theme="id"] {...}` token-override block) — no `crtBias`/`ambientTexture`/`borderImage`/structural keyframe overrides for any of the 9 (deliberately scoped to "color-only," matching how most existing packs are built; analog-90s's bespoke animation overrides are the exception, not the norm). Slugs: `master-control`, `cable-box-osd`, `ops-dashboard`, `prevue-guide-94`, `passport-03`, `cloud-guide-16`, `neo-brutalist`, `outrun-synthwave`, `frutiger-aero`. Two are genuinely light-background themes (`neo-brutalist` — cream/black/acid-yellow; `frutiger-aero` — sky-blue/white/teal-glossy), inverting the `--ink`(bg)/`--paper`(text) relationship every other theme in the app uses — both verified to render correctly with zero errors, including under the AUTO-CURATE/TAG TAXONOMY panels built earlier the same day, so the ink/paper inversion is safe precedent for any future light theme.

**Origin**: these 9 came from a design-research artifact ("Nine Signals," published as a Claude-artifact URL earlier the same session) built after the user asked for options before committing — 3 original broadcast-console concepts, 3 built from real EPG history (Prevue Guide's Amiga-over-VBI delivery, Pioneer Passport on PowerTV OS/GuideWorks' real "Blue Guide vs tan guide" split, the modern X1/RDK cloud-guide era), and 3 from current (2026) named design-trend research (neo-brutalism as an explicit anti-AI-design-default movement, sincere synthwave distinct from ironic vaporwave, Frutiger Aero's 2026 revival) — each with sourced citations. Only after the user explicitly said "build all 9 as new packs" (not replacing the existing 9) did implementation start.

**Verified**: booted the real app — confirmed `main-plugins.js`'s existing "auto-seed any bundled `plugins/<id>/` folder missing from `userData/plugins/`" logic (no manual copy needed, unlike the *editing an already-installed* plugin gotcha in [[retro_cable_box_cdp_autosave_gotcha]]) picked up all 9 new plugin dirs on the very next boot with zero errors, `themePackEntries()` returned 19 total (10 pre-existing incl. the zero-plugin `digital-2000s` default + 9 new). Screenshotted 5 of the 9 live against the real setup screen (Master Control, Cable Box OSD, Neo-Brutalist, Frutiger Aero, Outrun Synthwave) — every one correctly reskinned the entire setup UI (tabs, panels, sliders, checkboxes, buttons) via the shared token system, no component-specific breakage anywhere, including on panels built same-day (AUTO-CURATE, TAG TAXONOMY). Config was restored from backup after (theme selection is a real config write).

**Deliberate scope cut**: no new webfonts were sourced/bundled — the app is offline-first ([[retro_cable_box_architecture_constraints]]'s no-network-dependencies rule) and every existing theme's fonts are local `@font-face` woff2 files, so the mockup artifact's Google-Fonts-only display faces (Big Shoulders Display, VT323, Monoton, Comfortaa, IBM Plex Mono) were NOT carried into the real theme packs — all 9 reuse the 4 already-bundled families (`Archivo Black`, `Barlow`, `Barlow Condensed`, `Archivo Narrow`), differentiated via weight/case/tracking/color/radius instead of typeface swaps.

**Why:** the user wants a genuinely distinctive, non-generic UI and was willing to pay for real historical/design-trend research rather than a quick reskin — losing the "which theme is actually active vs. which exist" distinction, or the offline-first font constraint, would cause a repeat mistake (building fonts that silently 404/fall back at runtime, or redesigning `midnight-oled` under the wrong assumption that no alternative already existed).

**Depth pass shipped same day (2026-08-21)**: crtBias + bespoke power-on/off line animations added to all 9, plus 5 new locally-bundled webfonts (IBM Plex Mono, VT323, Fjalla One, Monoton, Comfortaa — `renderer/fonts/*.woff2`, `@font-face` in `tokens.css`), matching `analog-90s`'s depth for these two fields specifically (deliberately NOT adding `ambientTexture`/`powerSfx`/`channelChangeSfx`/`staticStyle`/`borderImage` — out of the scope the user actually asked for). Each theme's `crtBias` (`{scanlines,vignette,grain,flicker,curvatureFloor}` multipliers/floor, consumed by `applyCrtState`, `power.js`) and power-line `@keyframes` were hand-tuned to the theme's own identity (master-control: fast clean broadcast-monitor snap, near-zero bias; prevue-guide-94: heaviest bias + multiple uneven stutters, oldest signal chain; ops-dashboard/cloud-guide-16/frutiger-aero: minimal-to-no CRT character, modern flat panels; neo-brutalist: `steps()` hard-cut timing instead of easing; outrun-synthwave: slower glowing "power surge" pulse). Fonts assigned selectively, only to `--font-display` (large-scale text) where the face would be illegible as body copy (VT323 for cable-box-osd, Monoton for outrun-synthwave, Comfortaa for frutiger-aero), or to `--font-ui` where the face is body-legible (IBM Plex Mono for master-control and neo-brutalist).

**Real gotcha hit and confirmed live**: editing an *already-installed* bundled plugin's source in `plugins/<id>/` has zero effect on the running app — `main-plugins.js`'s auto-seed logic (`if (!fs.existsSync(destDir)) fs.cpSync(...)`) only copies bundled→`userData/plugins/` when the destination doesn't exist yet, so having boot-tested these 9 once already (which seeded the pre-crtBias versions) meant the crtBias/font additions were invisible until manually re-copying `plugins/<id>/` over `userData/plugins/<id>/` by hand. This is the exact gotcha [[retro_cable_box_cdp_autosave_gotcha]] already named in the abstract — this is the first time in this session it was actually hit and had to be diagnosed live (registry check showed `{label}` with no `crtBias` key at all, which is what pointed at stale-seed rather than a registration bug). **How to apply:** any time a bundled plugin that was already auto-seeded gets edited again, manually `cp -r plugins/<id>/. userData/plugins/<id>/` before the next boot test — don't trust the auto-seed to pick up source changes.

**Font-sourcing methodology** (useful precedent for any future theme needing a new webfont): fetched `https://fonts.googleapis.com/css2?family=<name>&display=swap` with a desktop Chrome UA (Google serves woff2-with-CORS only to modern UAs), grepped the CSS response for the `/* latin */` block specifically (skip `latin-ext`/`cyrillic`/etc. subsets — smaller file, sufficient for UI text) to get the real `fonts.gstatic.com` woff2 URL, then `curl`'d that URL directly into `renderer/fonts/<family>-<weight-name>-<weight-number>.woff2` matching the existing bundled-font naming convention, and added a matching `@font-face` block to `tokens.css`. Confirmed via `document.fonts.load()` + `.check()` (not just `.check()` alone, which lazily returns false until something on-screen has actually tried to render that family) that every font resolves with zero failed network requests — i.e. genuinely bundled/offline, not silently falling back to a Google Fonts CDN call the offline-first app would never make at runtime anyway.

**How to apply:** if asked to keep going on this — an `ambientTexture`/`powerSfx`/`channelChangeSfx`/`staticStyle`/`borderImage` pass to bring these 9 up to full `uhf-public-access-80s`-level depth is the natural next increment, matching the "4 new full theme eras (transition+screensaver+sound+guide-look+CRT-bias)" precedent from [[retro_cable_box_overview]]. If the user ever wants `midnight-oled` itself fixed/replaced rather than just adding alternatives, that's a distinct, smaller task (one pack's `style.css`) — don't conflate it with this 9-pack addition. FOSS sync for this batch was a plain recursive directory copy per the user's explicit "no need to verify FOSS as long as they stay in sync" — not independently boot-tested there, so the same stale-userData-seed gotcha could bite a future FOSS-side boot test if `userData/plugins/` there was ever seeded before this depth pass landed.
