Mid-session on 2026-08-05, the user paused the interstitials-spec work (see [[retro-cable-box-interstitials-spec-progress]]) to redesign the per-channel SCHEDULE tab, stating their real end goal: **recreate actual TV network programming blocks** — ABC Family's 25 Days of Christmas, a Disney Channel Friday movie premiere, Saturday morning cartoons, Noggin handing off to The N, AMC-style marathons. Everything below was scoped and built against that goal, not just "make it less cluttered."

**Shipped, all in `renderer/js/setup-schedule.js` + `renderer/css/setup.css` unless noted:**

- **Folder-less block invisibility fixed.** `matchingBlocks` (schedule.js) silently filters out any block with no folder/content — a block could match its trigger and just never air, with zero UI signal. New `blockHasContent()`/`matchingBlocksIncludingEmpty()` surface this as a red warning badge in the BLOCKS card, a striped-cell treatment in CALENDAR and TIMELINE, and text in the calendar day-detail panel. This directly caught a **real pre-existing bug on the user's own config**: channel 4 (Boomerang)'s Christmas block (Dec 1–25) had no folder ever assigned and was completely invisible everywhere (playback, guide, calendar) — now visibly flagged.
- **Block editor restructured** from one dense `flex-wrap` row (`.block-row`) into a `.block-card` with labeled sub-rows (header/schedule/mode/content) and a color swatch matching the block's color everywhere else (calendar, timeline). Caught and fixed a real overflow bug along the way: the TIME BLOCK/DATE RANGE toggle buttons were reusing `.block-day-btn`'s fixed 26px width (sized for 2-letter weekday abbreviations) and wrapping to two lines — new `.block-type-btn` modifier gives it auto width.
- **New TIMELINE view** — a 7×24 "broadcast/format clock" grid (the real broadcast-industry visualization for exactly this problem), added as the first view in the SCHEDULE tab's toggle (now TIMELINE / BLOCKS / CALENDAR). Samples `resolveActiveSource` hourly across the current real week — pure function of time, no new resolution math. This is the piece that makes a clean Noggin→The N-style full-day daypart handoff something you can *see* (gaps/overlaps), which CALENDAR's day-level view never showed since a `dayOfWeek` block's hour range had no visual at all before this.
- **CALENDAR de-emphasis for empty months** — a month with nothing but DEFAULT dims the grid (`.calendar-grid-wrap-quiet`, opacity 0.45) and shows a one-line notice instead of 31 identical cells competing visually with a month that actually has content; PREV/NEXT get a small gold dot when the adjacent month has something scheduled, so navigating isn't blind scrolling.
- **Weekly rotation mode for `dayOfWeek` blocks** (the one real *feature* gap, not just UI polish) — new `resolveWeeklyOccurrenceSource` in `schedule.js`, enabling the actual "Disney Channel Movie" case: a standing weekly slot (e.g. every Friday 8–10pm) that plays a different file from its folder each week instead of looping the whole folder. Only offered when a `dayOfWeek` trigger has exactly one day selected (single once-a-week occurrence to rotate against — no natural cadence for a multi-day trigger). Occurrence index counts from the block's own `anchor` (when its folder was assigned), weekday-aligned forward to the first real broadcast. Per-occurrence day overrides (pinning what a specific Friday plays) were explicitly **not** built — the existing `MM-DD` `dayOverrides` key scheme doesn't fit a recurring weekly slot, and it wasn't needed for the actual ask.
- **Compound triggers** (added mid-session when the user asked "can TIME BLOCK and DATE RANGE both be used at the same time?") — a `dateRange` trigger can now *optionally* also carry `startHour`/`endHour`/`days` fields (the exact same fields a `dayOfWeek` trigger uses), checked as an AND on top of the date match via new `matchesDateRangeNarrowing()`. This is what makes "25 Days of Christmas, but only 6–10pm" or "every Friday in October" (a Halloween movie night) actually expressible — before this, a block's trigger was strictly one shape or the other. UI: an "ALSO LIMIT TO SPECIFIC HOURS/DAYS" checkbox on `dateRange` blocks reveals the same hour-select/day-toggle controls a `dayOfWeek` block uses (refactored into a shared `buildDaysRow()` helper). Also fixed `nextSourceBoundary`'s daily-rollover fast path, which would have retuned at the wrong instant for a narrowed advent-mode block (it didn't know about the hour-window's end-of-day cutoff, only the next day's unlock).
- **Block presets** — a `+ ADD BLOCK ▾` menu offering four presets modeled directly on the user's named examples (25 DAYS OF CHRISTMAS, WEEKLY MOVIE NIGHT, SATURDAY MORNING CARTOONS, MOVIE MARATHON) plus the original two blank starting points, so recreating one of these is "pick a preset, point it at a folder."

**Real bugs caught during CDP verification, worth remembering the pattern of:**
- `cell.style.background = ...` (the `background` shorthand) silently resets `background-image`, which killed the CALENDAR empty-block stripe CSS pattern entirely until changed to `cell.style.backgroundColor`. Any future inline-style-driven cell coloring in this codebase should default to the specific longhand property, not the shorthand, when a CSS class might also be setting `background-image`.
- A stray empty block ended up on the wrong real channel (ch 5, "The Office Channel") mid-session from an early confused CDP script that had two edit panels open simultaneously and ambiguous row/button selectors — caught via the now-routine post-session config diff, hand-repaired (removed the stray block, reset `lastChannel` and `pictureMode` which had also drifted from other test interactions across the session) rather than a full restore, since legitimate new fields (`aspectMode`) needed to survive. Same "always diff before trusting" discipline as [[retro-cable-box-cdp-autosave-gotcha]], reinforcing that even *read-oriented* exploratory CDP scripts (not just explicit mutation tests) can accidentally mutate real state if selectors are ambiguous across multiple simultaneously-open UI panels — scope selectors to a freshly-confirmed single panel, don't assume `document.querySelectorAll` only matches the one you just opened.
