Two real bugs found and fixed 2026-08-21, both via live CDP investigation (relaunch + screenshot + computed-style inspection), core+FOSS synced.

**1. Party channel (CH94) showed solid black instead of its "JOIN THE PARTY" idle screen.** `showVirtualChannel()` (virtual.js) unconditionally un-hides `#plugin-channel-container` (z-index 5, opaque black — overlays.css) for every registered plugin channel. But party-channel's `render()` deliberately ignores that container and reveals its own pre-existing `.party-channel` DOM (z-index 4) instead — an intentional, documented deviation (see its renderer.js file header). With the container still shown-but-empty, its opaque black background painted directly over party's real content. Fixed generically (not with a per-plugin flag): only un-hide the container if `render()` actually put something in it (`innerHTML.trim()` non-empty after the call). Verified live: party channel now shows its QR/join screen; a container-based plugin (AUX/video-in, CH0) still renders correctly through the same code path.

**2. Theme-dependent UI overflow + oversized dropdowns — actually two separate root-cause bugs stacked together, both found via the neo-brutalist theme (uses a wider monospace `--font-ui: 'IBM Plex Mono'` vs the default condensed `Archivo Narrow`/`Barlow Condensed`), which exposed pre-existing, theme-independent layout flaws:**
  - `.settings-grid`'s panels are CSS grid `1fr` tracks, and `.panel-interval`'s selects live inside a nested flex row — but CSS grid/flex items default to `min-width: auto`, not `0`, so a select or checkbox label whose intrinsic content is wide enough (a long option string, or just a wider font) refuses to shrink to its track/row width and instead grows the whole card past its own border into the neighbor. Fixed with `min-width: 0` on `.panel`, `.panel-interval`, and `.panel-interval select` (renderer/css/setup.css) — lets the pre-existing `max-width:100%` + ellipsis truncation (tokens.css, from an earlier session) actually engage.
  - `.shuffle-toggle` (checkbox labels) had `white-space: nowrap` — fine for short chip-style toggles but a few (MOVIE MODE's full sentence) are long, and nowrap doesn't shrink text, it just lets it silently bleed past the panel with nothing to stop it. Removed nowrap so long labels wrap onto a second line instead.
  - Separately, and NOT theme-specific: the base `select { font-size: 15px !important }` rule (added in an earlier session to fix native `<select>` popups rendering smaller than their closed box under `#display-frame`'s transform) had clobbered every select's own per-context 11-13px declared size with a flat 15px — bigger than all surrounding label/button text everywhere, including at native resolution where there was never any transform mismatch to compensate for in the first place. Fixed: removed the flat 15px override (each select's own declared font-size stands again), and changed `select option { font-size: calc(15px * var(--display-frame-scale)) }` to `calc(1em * var(--display-frame-scale))` — `1em` in a `font-size` declaration resolves to the parent `<option>`'s inherited value (i.e. whatever THAT select's own actual font-size is), so the popup-legibility compensation now scales relative to each select's real size instead of assuming they're all 15px.

**3. Party channel's QR code never rendered (separate bug, found right after fixing #1).** `plugin-isolation-runtime.js` (Phase 2's per-plugin isolated-process runtime, see [[retro_cable_box_plugin_sandboxing_phase2]]) builds the `ctx` object handed to an isolated plugin's `activate(ctx)` — but it never included `QRCode` or `busboy`, even though party-channel (`manifest.json: "isolated": true`) destructures both from `ctx` (main.js: `getPartyJoinInfo()` calls `QRCode.toDataURL()`, wrapped in try/catch). `QRCode` being `undefined` threw inside that try/catch, silently swallowed — `url` still resolved fine (a different code path), only `qrDataUrl` came back `''`, leaving `<img id="party-qr">` with an empty `src` and no visible error anywhere. Only party-channel uses either package, so this had zero effect on the other 9 isolated plugins. Fixed by having the isolated runtime `require('qrcode')`/`require('busboy')` directly (same pattern as `getLanAddresses`/`getViewerUrls`, both pure Node with no Electron dependency — same node_modules tree, no RPC proxy needed) and adding both to the returned ctx. Verified live: QR image src is now a real base64 PNG, naturalWidth 320, renders correctly on screen. Likely also fixes party-page photo/video upload parsing (busboy), though that wasn't separately re-tested.

**How to apply:** when adding a new capability/dependency to `ctx` for the non-isolated plugin path (main-plugins.js), always check whether `plugin-isolation-runtime.js`'s `buildCtx()` needs the same addition — the two ctx-building paths are NOT automatically kept in sync, and a missing one fails silent-and-swallowed rather than loud, exactly like this bug. a UI element that looks fine under the default theme/font can still have a real, generic overflow bug that only a differently-metriced theme (wider font, different letter-spacing) happens to expose — the fix belongs in the base layout (min-width:0, wrapping, relative sizing), not a per-theme patch. See [[retro_cable_box_auto_display_mode]] for the display-frame-scale/transform machinery these fixes interact with, and [[retro_cable_box_setup_ui_bugs]] for the earlier (different) setup-screen bug-audit session.
