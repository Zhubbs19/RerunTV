Ticker, Screensaver, Vintage Audio Texture, and SMPTE Test Pattern were migrated to `plugins/ticker`, `plugins/screensaver`, `plugins/vintage-audio`, `plugins/smpte-test-pattern` on 2026-08-17, synced to both `retro-cable-box` and `retro-cable-box-foss` per [[retro_cable_box_foss_parity]].

**Why:** continuation of the plugin-ization effort in [[retro_cable_box_virtual_channels_as_plugins]] and [[retro_cable_box_plugin_migration_candidates]], but these four are different in kind — earlier migrations were self-contained virtual channels core called *into* via `registerChannelType`; these four are core subsystems that core itself used to own and call *from* several internal sites (theme change, power on/off, idle-timer, tune-to-unconfigured-channel). Migrating them required core to start calling *out* to the plugin instead, via small new `window.RCBPlugins.<id>` hook objects — a new direction for this codebase's plugin boundary, not just relocating self-contained code.

**How to apply / what to know if touching these again:**
- **Ticker**: `window.applyTickerState` is still the exact global name (matches the pre-existing `PLUGIN_DEVELOPMENT.md` "functions core exposes" table entry), but now the *plugin* assigns it rather than core — core (`app.js`, `party.js`'s `pushToTickerFeed`) calls `window.applyTickerState?.()` instead of importing it. The party-feed/static-text concatenation logic that used to live in `power.js` moved into the plugin unchanged.
- **Vintage Audio**: `THEME_TEXTURE_PROFILES` + the hiss/tone/crackle generator engine moved into the plugin; core's `themes.js`/`power.js` call `window.RCBPlugins?.vintageAudio?.applyThemeAudio?.()` at theme-change/power-on/power-off instead of an import. `playChannelClickSound` (checks `config.vintageAudio.clicks`) stayed in core `audio.js` as a general SFX helper — not moved. The pre-existing gap where `cutoffHz`/`hum` config knobs are exposed in the settings panel but never actually read by `applyThemeAudio()` was preserved as-is (not a regression from this migration, inherited from the original core code).
- **Screensaver**: full move including the interrupt guard checks (EAS-active/ad-break-active/time-machine-on/guide-open) — no new core-exposed state-accessor API was needed for this, since `window.S` (the live app-state object) was already exposed on `window` and the guide-grid element is reachable via a plain `document.getElementById('guide-grid')` from the plugin's own script, same-page DOM access. `S.screensaverTimer` was removed from `state.js` entirely — the plugin now owns its idle-timer id as a private module-scope variable, not shared app state. Core's `resetIdleTimer()`/`powerOff()` (`power.js`) and the setup-screen-open path (`app.js`) call `window.RCBPlugins?.screensaver?.cancelTimer?.()` / `scheduleTimer?.()` instead of the old `hideScreensaver()`/`scheduleScreensaverTimer()` functions.
- **SMPTE Test Pattern**: smallest/most self-contained of the four — only the draw function and settings panel moved; the `#test-pattern-canvas` element itself stayed core-owned in `index.html`/`dom.js` (deliberate choice, since it has no plugin-specific styling and the CRT power-off hide rule already applies generically). `playback.js`'s `tuneToChannel` `!ch` branch calls `window.RCBPlugins?.smpteTestPattern?.draw?.()`.
- All four keep their original config keys (`ticker`, `screensaver`, `vintageAudio`, `testPattern`) for backward compatibility — no config schema migration was needed, only code relocation.
- Verified via CDP boot test on both `retro-cable-box` and `retro-cable-box-foss` (zero console errors, all 4 `window.RCBPlugins.<id>` hooks present, settings panels render and contain the expected controls) — see [[retro_cable_box_cdp_autosave_gotcha]] for a new gotcha found during this verification (the portable-userData migration silently switching which config file is live mid-session).
