The user handed off a local spec file, `C:\Users\zhubb\Downloads\programming-blocks-and-interstitials-spec.md`, describing four connected systems: (1) programming blocks with date/time triggers and daily/weekly/marathon modes, (2) a tagged-interstitial pool replacing hardcoded per-channel bumpers, (3) a visual calendar UI, (4) a daily customizer for per-date overrides. **Done, 2026-08-05, session A (schema unification):** `ch.blocks[]` and the older `ch.dateOverrides[]` were unified into one `ch.blocks[]` array driven by a `trigger` object (`type: 'dayOfWeek'` or `'dateRange'`) plus `priority`/`mode`. `mode: 'daily'|'weekly'` (the advent-calendar mechanic) is implemented — day-index selection, `dayOverrides` (pin a file/title/custom unlock time/skip a day), and `finale` (unlock-all + marathon on the last day) all work, scoped to `dateRange`-trigger blocks only (a `dayOfWeek` trigger has no natural "day 1" to count from, so the mode selector is hidden for those). `premiereIdent` was deliberately dropped from scope at the time — it had zero effect before tagged interstitials existed to hook a jingle into. Verified via a real Electron boot test against the user's actual 13-channel config, including day-index advance, unlock-time gating, skip, and finale, by fast-forwarding `S.timeOffsetMs`.

**Done, 2026-08-05, session B (tagged interstitials, folding in the existing systems):** Built `renderer/js/interstitials.js` — a shared `S.config.interstitials.pool` of `{type, channelAffinity, blockAffinity, weight, file, text}` entries, selected via `resolveBreakAt(ch, atMs)`, a deterministic pure function (see [[retro-cable-box-architecture-constraints]] for why this matters and how the selection math works). Per user's explicit choice, this pass folded in ALL of the existing commercials/station-ID/trivia systems (not just the spec's suggested minimal channelId+upNext slice) into one pool and one selection engine — `commercial` (was ad bumpers), `channelId` (was station ID, still falls back to auto-generated "YOU'RE WATCHING <channel>" text when the pool has no entries for it), `trivia` (was the flat facts[] list), plus a new `upNext` type (optional video idents, additive to the pre-existing automatic text banner which was left untouched). This also directly satisfied a second ask from the same session — the time machine (VCR shuttle) now shows exactly what commercial/trivia/station-ID would be airing at any scrubbed instant, past or future, because `timemachine.js`'s preview calls the identical `resolveBreakAt` live playback uses.

**Done, 2026-08-05, session C (aspect ratio + ad pods + signOn/signOff + CRT curvature):** `S.config.aspectMode` ('contain'/'stretch', key `A`) mirrors the existing picture-mode toggle pattern exactly. Ad pods: `cc.podMin`/`podMax` (default 1/1, exactly backward-compatible) plus new `adBreakIn`/`adBreakOut` pool types, resolved via a new `buildPod()` in `interstitials.js` that chains bump-in → N commercials → bump-out as consecutive deterministic windows — required zero changes to `playback.js` since the existing `ended`-event → `checkBreakState` → re-resolve cycle already walks consecutive windows naturally. **signOn/signOff broadcast-day**: new `ch.broadcastHours = {enabled, startHour, endHour}` (default off, `endHour:0` means "until midnight" — chosen over `24` so the setup UI's 0-23 hour `<select>` can represent it), `isWithinBroadcastHours`/`nextBroadcastHoursBoundary`/`prevBroadcastHoursBoundary` (schedule.js) gate `tuneToChannel` (playback.js) into a calm gold "SIGN-OFF" card outside the window, with one `scheduleBroadcastHoursRetune` timer handling both sign-off and sign-on transitions (both are just "run `tuneToChannel` again"). `signOn`/`signOff` pool types play as ordinary breaks in the closing/opening seconds of the broadcast day — needed *both* a forward (`next`) and backward (`prev`) boundary lookup, since a few seconds after sign-on the channel already reads as "within hours" and the forward-only function can't find the boundary just crossed. **CRT curvature**: new `crtIntensity.curvature` slider (0-100, default 0/off) alongside the existing four, driving a `border-radius` on `.crt` plus a second tighter edge-vignette layer — grouped with and gated by the existing CRT-effects-off toggle (curvature flattens to 0 when CRT effects are off, consistent with living in the same settings group). All four verified via CDP boot tests against scratch channels/pure-function tests; config diffed clean after each. See [[retro-cable-box-cdp-autosave-gotcha]] for two real gotchas hit along the way (the `window.confirm()` CDP hang, and `style.background` shorthand silently killing a CSS `background-image`).

**Done, 2026-08-05, session D (block theming):** `block.theme = {accent, accent2, staticTint} | null` on any `ch.blocks[]` entry, editable via a THEME button/lazy panel next to ADS in `buildSchedulePanel` (three `<input type="color">` fields + CLEAR). New `applyBlockTheme(block)` (power.js) sets `--block-accent`/`--block-accent2` on `.crt` (removed, not just left stale, when unthemed — called both from `playChannelLive` on every play and reset at the top of every `tuneToChannel` so a themed block's colors never bleed into a channel that doesn't reach playback that tune, e.g. sign-off/coming-soon/virtual). Consumed via `var(--block-accent, var(--gold))`-style fallbacks in `overlays.css` (crt-toggle-flash, up-next bar) and `var(--block-accent2, var(--cyan))` (station-id bar) — untouched/default for the overwhelming common unthemed case. `staticTint` blends the channel-change static burst's noise toward the block's color (`showStaticBurst`, playback.js, now takes an optional tint param). Guide-grid coloring: `walkSourceSchedule` (schedule.js) now attaches `block: source.block` to every schedule entry it builds, and `buildChannelRow` (guide.js) applies a themed entry's `border-left-color` from it — opt-in only, no visual change for untouched schedules. Verified via a pure-function test (block/theme correctly threads through `getChannelSchedule`/`resolveActiveSource`) plus a live CDP test (THEME panel UI, and confirming `--block-accent` stays correctly empty/unset — falling back to gold in computed style — on an unthemed real channel).

**Done, 2026-08-05, session E (promo/leadDays + a major shared-engine bug fix):** New `promo` pool type — "This Saturday: [movie]" bumpers counting down to an upcoming `dateRange` block's premiere. Unlike every other type, a promo entry's `channelAffinity`/`blockAffinity` name the block being *promoted* (not "which block this plays during") — reused those existing fields rather than adding new targeting fields, plus one new `leadDays` field (setup UI gated by a new `needsLeadDays` flag on the type-def table). New `nextBlockStartMs(block, fromMs)` export (schedule.js) — forward-looking-only, deliberately different from the existing module-private `cycleStartMs` (which finds the cycle *containing* a day, including an already-started one) since a promo should stop being eligible once its target has actually started airing. New `eligiblePromoEntries` (interstitials.js) filters the pool to entries currently inside their own `leadDays` countdown window, resolved at content boundaries via the same mechanism `upNext` already used.

**Building promo surfaced a significant pre-existing bug, now fixed**: `upNext`, `promo`, and commercial `pre`/`post`/`both` timing all anchor their break window to `boundarySlot()`'s `fileEndMs` — but `fileEndMs` is *always in the future* relative to whatever instant computed it (it's "when the file currently notionally playing will end"), so `windowStart >= atMs` can only ever be satisfied by exact floating-point equality — which real-world polling (even the natural HTML5 `ended` event, let alone the timer-based path with its 250ms buffer) essentially never hits. Confirmed via a live pure-function test: a plain `upNext` entry driven through the real `nextBreakBoundary`/`checkBreakState` scheduling functions returned `Infinity` — it silently never fired, and never had, independent of anything built this session. **Fix**: anchor to `fileStartMs` instead (`= atMs - offset*1000`, always `<= atMs` by construction, so it correctly represents "how long ago the most recent boundary passed" no matter how far real-time polling has drifted past it) — a one-line change at each of the three call sites (`interstitials.js`). Verified via pure-function tests that `upNext`, commercial `both` timing, and `promo` all now fire correctly through the real scheduling path, and that ad pods/signOn-signOff (which use different, unaffected timing mechanisms — `intervalSlot`/`nextBroadcastHoursBoundary`) still pass unchanged. **How to apply**: if a future `everyNMinutes` or other new boundary-tied break type is added, anchor it to `fileStartMs`-style "most recent boundary" math, never `fileEndMs`-style "upcoming boundary" math, for the window-start — the latter is correct for scheduling *when to next check* (`nextCandidateBoundary`'s own candidate-push use of `fileEndMs` is fine and unchanged) but wrong for the window itself.

**Done, 2026-08-06, session F (dynamic bumpers + everyNMinutes — closes out the spec except premiereJingle):**
- **Dynamic bumpers**: `entry.dynamic` is now an orthogonal flag on any video-kind pool entry (commercial/upNext/channelId/adBreakIn/adBreakOut/signOn/signOff/promo) — a DYNAMIC checkbox in the pool editor (setup-interstitials.js) swaps the plain file picker for a background-clip picker (`bgFile`) + a template text field (reusing the existing `text` field, now meaning "template" instead of "literal") + an author-set `durationS` (a looping background has no natural length the way a probed file does — new `entryDurationS()` helper in interstitials.js centralizes this rule for windowFor/windowEndingAt/buildPod, replacing the repeated `entry.file ? entry.file.duration : fallback` ternary everywhere). Playback (`startBreak`, playback.js): sets `player.loop = true` and the background as `player.src`, renders templated text into a new `#dynamic-bumper-text` overlay via `renderDynamicText()` supporting `{channel}` `{time}` `{nextTitle}` `{daysUntil}` — deliberately skips attaching an `ended`-triggers-resume listener (loop=true never fires it), relying entirely on the existing boundary timer to cut it off on schedule, exactly like every other break type already does.
- **`{daysUntil}`**: resolves only for a `promo` entry with a real target block, via `nextBlockStartMs` — this is what makes the High-School-Musical/SpongeBob-"Truth or Square"-style escalating countdown the user described actually work: the same promo entry's on-screen number counts down day by day as the premiere approaches, computed fresh each time it airs rather than being static copy.
- **`everyNMinutes`**: a new `commercials.timing` value — mid-video ad breaks *within* the currently-playing file, not just at whole-file boundaries. Slots every `intervalMinutes` from the file's own real start (`boundarySlot(source, atMs).fileStartMs`), explicitly skipping slot 0 (the file's own start — already the boundary-tied timing modes' domain) and any slot spilling past the file's real end. Needed **zero changes** to the resume mechanism — `endBreak` already credits real elapsed break time back via `S.contentLostMs` regardless of *why* content stopped, so "resume the show where it left off" works identically whether the break was between files or mid-file.
- Both verified via pure-function tests (dynamic entry duration/window correct; everyNMinutes breaks land exactly N minutes apart, correctly skip the pre-slot-1 window, no spillover past file end) plus live CDP UI checks (DYNAMIC checkbox reveals the right fields; `everyNMinutes` appears correctly in the timing dropdown with its interval field). Config diffed clean after repairing unrelated drift carried over from the same session's earlier universal-remote testing (lastChannel/volume/pictureMode) — a reminder that a fresh pre-boot backup should be taken at the start of each new work chapter, not reused across very different feature areas in the same sitting.

**Done, 2026-08-09, session G (contentLostMs pod-transition bugfix + breakpoints timing + ad presets):**
- **Bugfix**: user reported "the show's timeline keeps advancing even though the commercial displays correctly." Root cause: `checkBreakState` (`playback.js`) only credits elapsed break time to `S.contentLostMs` inside `endBreak` — but a multi-segment ad pod (`adBreakIn` → `commercial` → `commercial` → `adBreakOut`, each with its own `windowStart` per `buildPod`) never calls `endBreak` between segments, since `resolveBreakAt` keeps returning a break the whole time; it only goes through the "key changed, `startBreak` again" branch. Every segment but the pod's last one had its content-lost time silently dropped, so the show's computed position (`viewNow() - S.contentLostMs`) crept ahead by the sum of all-but-the-last segment's duration. Confirmed live via a CDP test against the real config's channel 73 (Boomerang, `podMin:2/podMax:4`): a real 5-spot pod spanning ~51.7s only credited ~9.9s (the last segment alone) pre-fix; post-fix credits the full 51.7s. Fix: `checkBreakState` now credits `viewNow() - S.breakEnteredAtMs` to `S.contentLostMs` on every segment-to-segment key change (not just on the final transition to "no break"), gated on `S.activeBreakInterruptsContent` exactly like `endBreak` already does.
- **`breakpoints` timing mode**: new `commercials.timing` value — explicit % positions through the currently-playing file (e.g. `[20, 50, 80]`) instead of a fixed N-minute cadence (`everyNMinutes`) or per-file pre/post. Implemented in both `resolveBreakAt` (the actual break window) and `nextCandidateBoundary` (so the boundary-timer scan finds it) in `interstitials.js`, anchored to `boundarySlot(source, atMs).fileStartMs` the same way `everyNMinutes` already is. Setup UI: a BREAKPOINTS option in the per-channel/block ADS panel's BREAKS dropdown (`setup-panels.js`) plus a comma-separated `%` input field.
- **Ad presets** (`S.config.interstitials.presets[]`, new PROGRAMMING-tab panel in `setup-interstitials.js`): named, reusable break-layout objects (`{id, name, enabled, contentTags[], timing, intervalMinutes, breakpoints[], podMin, podMax}` — literally the same shape `resolveActiveCommercials` already returns for a block/channel) that get matched by **content tag** (reusing the existing per-file `tags` field, TITLES tab) rather than assigned directly to a channel or block. `resolveActiveCommercials(ch, atMs, fileTags)` (`schedule.js`) now checks for a tag-matching enabled preset *before* falling back to the existing block-priority/channel-default logic — a preset match wins outright, since the point is "this exact show" beating "this whole block/channel." This is the concrete answer to "ad presets for different show types" (30-min cartoon w/ 2 episodes, 1-hour show, 2-hour movie, etc.) — tag the relevant files once, then a preset targeting that tag governs ad timing for that content everywhere it airs. Ad-selection `seedKey` in `resolveBreakAt` now keys off the preset id (when one governs) instead of the airing block, so a preset's picks travel with the tagged show rather than resetting when it airs on a different block; existing non-preset configs keep their exact prior seed (`block.id`/`'default'`) so nobody's current ad rotation shuffles from this change.
- Both new features and the bugfix verified via CDP: a pure-function pod-transition simulation (bugfix), a pure-function preset-tag-match + breakpoints-at-50%-fires-correctly test against real channel 6 (Spongebob) content, and real DOM click-tests (add/edit/remove a preset in the new panel; switch a real channel's ADS timing to BREAKPOINTS and set values) — all with `window.onerror` capture and a clean post-test config diff (the only committed diff was the intended `presets: []` migration default).
- Two design choices were confirmed with the user up front rather than assumed: mid-show timing control is numeric %-based, not a visual drag timeline (bigger UI investment, not requested at the time); presets are targeted by content tag, not by duration bucket or direct per-channel assignment (tag-based lets a single channel mix show types cleanly, matching the existing contentTags mental model the pool editor already uses).
- **2026-08-16 addendum**: the deferred visual drag timeline got built after all — `buildBreakpointTrack` (setup-util.js, shared by both the per-channel/block ADS panel in setup-panels.js and the PROGRAMMING-tab presets in setup-interstitials.js) is a click-to-add/drag-to-move/click-to-remove 0-100% track, kept in sync with the pre-existing comma-list text field in both directions rather than replacing it. Verified by dynamically importing the module in a live CDP page context and dispatching real mouse events (click adds a pin at the right %, drag repositions and updates the text field, a click-without-drag removes a pin, correctly nulling `breakpoints` when the last one goes — matching the array's existing null-when-empty convention).

## Era-authenticity ideas that give concrete motivation for the still-unbuilt pieces above (2026-08-05)

Asked for programming/commercials/blocks ideas that "feel true" to 90s-2000s cable, several of which resurface the "not built" items above with a real reason to build them, rather than just "the spec listed it":

- **Real ad "pods"** — a bump-*into* a break, 2-4 `commercial` entries back to back, a bump-*out*/return promo — instead of always resolving one entry per break window. This is the concrete case for building `adBreakIn`/`adBreakOut` types.
- **Sign-on/sign-off broadcast day** (color bars/test pattern overnight before returning at a set hour) — the spec deferred `signOn`/`signOff` "unless/until time-of-day broadcast-day scheduling exists"; that prerequisite now exists (`timeWindow`/`dayOfWeek` triggers, shipped this session), so the deferral reason is gone. Strongest on a channel styled as local/public-access.
- **Weekly "coming up" promo bumpers** ("This Saturday: [movie]") tied to an upcoming `dateRange` block starting — concrete texture for the still-unbuilt `promo`/`leadDays` feature.
- **PSAs as their own pool `type`** — cheap (just another row in the eventual data-driven type table, see [[retro-cable-box-quality-of-life]]), authentic basic-cable texture.
- **Content-advisory pre-roll card** before higher-rated content — extends the existing rating bug into a brief timed interstitial rather than only a corner badge.
- **"Paid programming" late-night block** with a small disclosure bug — just a themed `timeWindow` block + badge, no new mechanism, but a fun, authentic pattern worth calling out as a **block preset/template** (see [[retro-cable-box-quality-of-life]]'s Tier 4 promotion note) alongside "SATURDAY MORNING CARTOONS," "WEEKDAY AFTERSCHOOL," "HOLIDAY MARATHON."

Separately, viewer-experience (not programming-logic) era-authenticity ideas from the same conversation — scrambled/unsubscribed premium channel effect, 4:3 pillarboxing, a dedicated "VIDEO IN"/AUX channel, VHS-sourced picture quality on local channels, audio texture tied to the `digital-2000s`/`analog-90s` guide theme, a "please call your cable company" blocked-channel card — live in [[retro-cable-box-feature-backlog]] instead, since they're viewer-facing content/atmosphere features rather than programming-blocks/interstitials-system work.
